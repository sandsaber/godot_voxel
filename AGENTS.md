# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository. Read this
first.

## What this project is

A voxel terrain engine for Godot 4, **fully ported from the original C++ module
[Zylann/godot_voxel](https://github.com/Zylann/godot_voxel) to pure Rust**. It
ships as a Godot GDExtension (`.so`/`.dylib`/`.dll`). The C++ module is gone;
the Rust port is the source of truth.

The Rust code lives entirely under [`rust/`](rust/). The rest of the repo root
is legacy Godot-module scaffolding that is no longer used.

## Crate layout

A single Cargo workspace at `rust/`:

| Crate | Role | Knows about Godot? |
|---|---|---|
| [`voxel-core`](rust/voxel-core/) | The engine: math, storage, meshing, generation, terrain, streams, format. All hot paths. | **No** — pure Rust, `cargo test` without Godot. |
| [`voxel-gdext`](rust/voxel-gdext/) | Thin Godot 4 GDExtension binding. `#[func]`/`#[var]` wrappers that delegate to `voxel-core`. 79 classes. | Yes — only crate depending on the `godot` crate. |
| [`tsan`](rust/tsan/) | ThreadSanitizer tests (concurrency / paging / locks). | No. |
| [`fuzz`](rust/fuzz/) | `cargo-fuzz` / libFuzzer targets for byte-level parsers (vox, block_serializer, region_file). Separate workspace. | No. |
| `cpp-baseline` | C++ reference harness that regenerates parity golden data. Not part of the runtime. | — |

**The voxel-core ↔ voxel-gdext boundary is critical.** All logic and the entire
hot path live in `voxel-core` and never pay FFI cost per call. `voxel-gdext` only
converts types and forwards. Keep new logic in `voxel-core`, wrapped (if needed)
by a thin `#[func]` in `voxel-gdext`.

## Architecture: the data pipeline

The full pipeline runs end-to-end in pure Rust (no engine dependency), exercised
by `voxel-core`'s tests:

```
GraphGenerator (24+ node kinds: SDF/Curve/Noise/math/IO; uniform output compression)
   │  or  Waves / Flat / Noise / HeightmapNoise (simple generators; shared Arc curve)
   ▼
VoxelData  (SharedVoxelData worker handle: settings lock + per-LOD map RwLocks + SpatialLock3D)
   ▼
MeshBlockTask  (gather_voxels_cpu: 3×3×3 neighbours + generator gap-fill; SharedVoxelMesher = Arc<dyn VoxelMesher>)
   ▼
VoxelMesher  ◂── TransvoxelMesher (smooth SDF, regular cells, uniform fast-path)
            ◂── CubesMesher      (greedy/simple, palette)
            ◂── BlockyMesher     (voxel-model library + AO)
   ▼
MesherOutput { surfaces: Vec<Surface>, collision_surface }
   ▼
VoxelTerrainCore (paging orchestrator: paired viewers → data/mesh box diffing → load/mesh/unload)
   ▼
VoxelEngine foundation (generational volume/viewer registry, owns ThreadedTaskRunner)
```

Key modules in `voxel-core/src/`: `storage/` (VoxelBuffer, VoxelData, channels),
`meshers/` (transvoxel/blocky/cubes), `generators/` (graph, waves, flat, noise,
fast_noise2), `streams/` (region files, memory, compressed, save/load),
`terrain/` (VoxelTerrainCore paging), `tasks/` (threaded task runner),
`edition/`, `instancing/`, `modifiers/`, `format/vox/`.

## Class-naming scheme (important)

`voxel-gdext` registers Godot classes under **canonical names matching upstream
C++** (`VoxelBuffer`, `VoxelMesherBlocky`, `VoxelTerrain`, …) via the
`#[class(rename = ...)]` attribute. The Rust structs keep a `GD` suffix
internally (`VoxelBufferGD`); ClassDB and GDScript see the canonical name.

- When adding a class whose Rust struct ends in `GD`, add `rename = <Canonical>`
  to avoid leaking the suffix.
- Three classes use a `ZN_` prefix because the bare name clashes with a Godot
  builtin (matches upstream C++): `ZN_FastNoiseLite`, `ZN_SpotNoise`, `ZN_Curve`.

## Build, test, verify

All commands run from `rust/`:

```sh
cargo build --workspace                 # build everything
cargo test --workspace                  # 1494 tests (0 failed, 4 ignored)
cargo clippy --workspace --all-targets  # must be warning-clean
cargo fmt --check                       # must pass
cargo build -p voxel-core --target aarch64-linux-android   # cross-compile (pure-Rust core)
```

> For loading the built extension into a Godot project (desktop + Android + iOS,
> debug vs release, the `.gdextension` setup), see
> [`rust/docs/INTEGRATION.md`](rust/docs/INTEGRATION.md).

Toolchain is pinned in `rust/rust-toolchain.toml` (Rust 1.96.1).

### Test categories

- **voxel-core unit** (`src/`): 800 — the bulk of correctness tests.
- **parity** (`tests/parity_suite.rs`): 674 — Rust re-ports of the upstream
  C++ unit tests, hand-computed expected values, and regression pins measured
  from the Rust implementation. They catch regressions and validate semantics,
  but they do **not** read C++ golden data.
- **integration** (`tests/end_to_end_pipeline.rs`): 5 — pipeline with a toy
  mesher (the real full pipeline is covered by the `terrain_parity` modules in
  `parity_suite.rs`).
- **transvoxel parity / sphere / tables**: 5 — the only tests that compare
  against C++ golden data generated by `cpp-baseline` (bit-exact
  indices/masks/counts, 1e-5 float tolerance).
- **stress**: 1 (`threaded_edit_load_mesh_stress.rs`).
- **TSan** (`tsan/`): 5 — data-race checks (sanitizer instrumentation needs
  Linux + `cargo +nightly -Zbuild-std`; elsewhere they run as plain
  concurrency tests).
- **voxel-gdext unit** (`src/`): 3.
- **doc-test**: 1.

### Godot smoke tests

The Godot integration is verified with `rust/voxel-gdext/smoke_test/` (a real
Godot 4.7 project). The `.so` is a git-ignored build artifact, so on a clean
checkout build it first via the driver:

```sh
cd rust
./voxel-gdext/smoke_test/run_smoke_test.sh          # builds .so + runs all 3 checks
```

It runs `api_test.gd` (class registration + `#[func]` surface), `runtime_scene.tscn`
(terrain + generator + viewer paging, real frames), and `smoke_test.tscn`.
Requires `godot` (4.7+) on `PATH`.

## Conventions

- **No `unsafe`** in `voxel-core` production code (`#![deny(unsafe_op_in_unsafe_fn)]`;
  the only `unsafe` is in test helpers and `voxel-gdext`'s required
  `ExtensionLibrary` impl).
- Clippy clean, `cargo fmt` clean — enforced.
- Prefer returning `Result`/`Option` over `unwrap`/`expect` in production paths.
- New Godot-exposed methods: `#[func]` in `voxel-gdext`, delegating to logic in
  `voxel-core`.

## Known deferred / out-of-scope features

Not ported (tracked separately, intentionally omitted): GPU path (`gpu`,
`detail_rendering`, shaders), `sqlite` streams, `multipass` generator, physics
(Rapier). `voxel-core` deliberately stays pure-Rust (no C deps) so it
cross-compiles to Android/WASM cleanly.
