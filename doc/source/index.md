# Voxel Tools for Godot (Rust)

A voxel terrain engine for [Godot Engine 4](https://godotengine.org), fully
ported from the original C++ module
[Zylann/godot_voxel](https://github.com/Zylann/godot_voxel) to **pure Rust**.
It ships as a GDExtension (`.so` / `.dylib` / `.dll`) and loads into Godot
4.7+.

## What this is

- **Realtime 3D terrain** editable in-game: overhangs, tunnels,
  creation/destruction.
- **Transvoxel meshing** of signed distance fields, with LOD transition
  cells — smooth, polygon-based terrain.
- **Cubes (greedy) meshing** for Minecraft-style colored-voxel terrain.
- **Streaming**: generators, in-memory streams and `.vxr` region files on
  disk; viewer-driven block paging.
- **Procedural generation**: flat / waves / noise / heightmap-noise /
  image-driven generators, plus a node-graph generator.
- **Engine-agnostic core**: all logic lives in `voxel-core`, a Godot-free
  Rust crate with ~800 unit tests; the Godot layer (`voxel-gdext`) is a thin
  binding that forwards to it.

## How the port relates to the original

The Rust port is a clean-room reimplementation of the engine-agnostic half of
the C++ module, verified against the original where possible:

- The transvoxel lookup tables and regular-mesh output are compared against
  goldens generated by compiling the *real* upstream C++ code
  (`cpp-baseline` harness) — indices/masks/counts bit-exact, floats within
  1e-5.
- Hundreds of unit tests are Rust re-ports of the upstream C++ test suite.

See [Status & roadmap](status.md) for exactly what is implemented, what is a
stub, and what is intentionally deferred (GPU path, SQLite streams, physics
backends).

## Project layout

| Crate | Role |
|---|---|
| `voxel-core` | The engine: math, storage, meshing, generation, terrain paging, streams. No Godot dependency. |
| `voxel-gdext` | Godot 4 GDExtension bindings (79 classes). The only crate touching the `godot` crate. |
| `cpp-baseline` | C++ reference harness that regenerates parity golden data (not part of the runtime). |
| `tsan` | ThreadSanitizer concurrency tests. |
| `fuzz` | libFuzzer targets for byte-level parsers. |

Architecture details: [Concepts → Architecture](concepts/architecture.md).
